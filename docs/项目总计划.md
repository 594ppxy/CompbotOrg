# AI Organization OS — 项目总计划（修订版）

> From AI Agents to AI Organizations.
>
> 一个开源、纯公益的 AI 组织操作系统：让用户管理一个 AI 组织，而不是管理几十个孤立 Agent。

---

## 0. 修订说明

本计划在原始版本基础上进行了重大修订：

### 技术路线调整

| 原计划 | 修订后 |
|--------|--------|
| DSH + DSHBot + OpenBot 以适配器方式接入 | **以 DSH 为底层 Runtime 基础，深度改造 Tobs（BotHarness/DeepSeekBot）为核心** |
| 从零搭建 Organization Core | **在 Tobs 已有的 PersonaBot / Orchestrator / Assignment / Channel / Memory 架构上扩展** |
| OpenBot 作为可选 Runtime Adapter | **放弃 OpenBot（开源不够自由），Browser/Computer Use 复用 Tobs 已有能力** |

### 核心决策

1. **DSH 是底层 Runtime**：直接基于 deepseek-harness 代码，不作为外部依赖
2. **Tobs 是核心应用层**：直接基于 BotHarness/DeepSeekBot 代码深度改造
3. **不需要重新发明 PersonaBot、Memory、Channel、Assignment** — Tobs 已经实现了这些
4. **需要新增的是：组织层级（Organization / Department / Hierarchy）、治理（Governance / Approval / Audit）、Artifact 文件系统**

## 1. 项目定位

本项目不是普通的 Multi-Agent 聊天框架，也不是简单的 Agent Swarm。

核心目标：

- AI 可以组成真正的组织
- Bot 具有角色、职位、部门、上下级关系
- 管理者可以委派、审核、批准、驳回、升级任务
- Bot 之间通过结构化协议协作，同时保留自然语言交流
- 每个 Bot 拥有隔离的计算环境和工作空间
- 文件以 Artifact 为核心进行安全共享
- 组织、部门、Bot 分层拥有独立 Memory
- 后期建立类似 WorkBuddy 的专家 Skill / Connector 生态

核心理念：

> Message != Work

> Bots don't share folders. They share artifacts.

> Bot 是数字员工，Skill 是专业能力，Connector 是连接外部世界的能力，Runtime 是数字员工的身体。

### 5.2 新增模型

```typescript
// 组织
interface Organization {
  id: string
  name: string
  description: string
  ceoBotId: string           // 组织最高管理者
  departments: Department[]
  memory: OrganizationMemory  // 组织级记忆
  policies: Policy[]
  createdAt: string
}

// 部门
interface Department {
  id: string
  orgId: string
  name: string
  directorBotId: string      // 部门负责人
  members: BotMembership[]
  memory: DepartmentMemory    // 部门级记忆
  parentDepartmentId?: string
  createdAt: string
}

// Bot 在组织中的成员身份
interface BotMembership {
  botId: string               // PersonaBot ID
  departmentId: string
  role: Role
  reportsTo: string           // 上级 Bot ID
  manages: string[]           // 下属 Bot IDs
  permissions: Permission[]
  status: 'active' | 'suspended' | 'removed'
  joinedAt: string
}

// 角色
interface Role {
  id: string
  name: string                // CEO / CTO / Engineer / Researcher
  level: number               // 层级：0=CEO, 1=C-level, 2=Director, 3=Manager, 4=Worker
  permissions: PermissionTemplate[]
  canDelegate: boolean
  canApprove: boolean
  canEscalate: boolean
  defaultSkills: string[]     // 角色默认技能
}

// Artifact（文件系统核心）
interface Artifact {
  id: string
  type: 'report' | 'dataset' | 'code' | 'image' | 'video' | 'webpage' | 'model' | 'result' | 'document'
  title: string
  description: string
  creatorBotId: string
  ownerScope: 'org' | 'department' | 'bot' | 'project'
  ownerPath: string            // botfs://org/ 或 botfs://department/xxx/
  versions: ArtifactVersion[]
  permissions: ArtifactPermission[]
  tags: string[]
  createdAt: string
}

interface ArtifactVersion {
  version: number
  contentHash: string
  size: number
  createdAt: string
  createdBy: string
  changeLog: string
}

// 治理
interface Policy {
  id: string
  name: string
  description: string
  trigger: PolicyTrigger      // 何时触发
  action: PolicyAction        // 需要什么操作
  approver: 'human' | 'manager' | 'auto'
  scope: 'org' | 'department' | 'bot'
}

interface AuditEvent {
  id: string
  actor: string               // Bot ID 或 User
  action: string
  target: string
  timestamp: string
  reason: string
  result: 'success' | 'denied' | 'error'
  details: Record<string, unknown>
}
```

## 6. 改造方案

### 6.1 改造 PersonaBot → 组织成员

Tobs 的 `PersonaBotRecord` 已经有：slug, displayName, roles, tag, description, model, memoryDir, workspaces。

**需要扩展：**

```typescript
// 在 PersonaBotRecord 基础上扩展
interface OrganizationBot extends PersonaBotRecord {
  // 已有字段保持不变
  // 新增：
  organizationId?: string
  departmentId?: string
  role?: string               // Role ID
  reportsTo?: string          // 上级 Bot ID
  manages?: string[]          // 下属 Bot IDs
  authority?: string[]        // 权限列表
}
```

**改造方式：** 在 Tobs 的 `packages/core/src/bots/persona-bot.ts` 中扩展 `PersonaBotRecord`，增加组织字段。

### 6.2 改造 Orchestrator → 管理者

Tobs 的 Orchestrator Session 已经是 Bot 主管调度模式。

**需要扩展：**
- 增加 **委派（Delegate）** 能力：管理者可以将任务委派给下属
- 增加 **审核（Review）** 能力：管理者可以审核下属的报告
- 增加 **升级（Escalate）** 能力：下级可以向上级升级问题
- 增加 **批准/驳回（Approve/Reject）** 能力

**改造方式：** 在 Tobs 的 Orchestrator 相关代码中增加组织协议工具。

### 6.3 改造 Team Task Board → 组织任务

DSH 的 `TeamTaskBoard` 已有：create, claim, release, complete, reopen, reassign, delete。

**需要扩展：**
- 增加 `assign` 操作：管理者直接指派任务
- 增加 `delegate` 操作：向下委派
- 增加 `review` 操作：审核报告
- 增加 `escalate` 操作：向上升级
- 增加 `approve` / `reject` 操作

**改造方式：** 扩展 DSH 的 `packages/team/agent-team/src/task-board.ts`。

### 6.4 改造 Memory → 三层 Memory

Tobs 的 Memory 已有：SOUL.md（人格）、MEMORY.md（核心记忆）、Git 版本化。

**需要扩展为三层：**

| 层级 | 内容 | 实现 |
|------|------|------|
| Organization Memory | 战略、政策、组织知识、重大决策 | 新增 `botfs://org/memory/` |
| Department Memory | 部门目标、工作流程、专业知识、项目经验 | 新增 `botfs://department/{id}/memory/` |
| Bot Memory | 工作经验、任务历史、偏好、失败经验 | 复用 Tobs 已有 Memory |

**改造方式：**
- Bot Memory 保持 Tobs 现有实现
- 新增 Organization Memory 和 Department Memory 模块
- Memory 检索支持跨层级查询

### 6.5 新增 Artifact FS

Tobs 已有 workspace（目录授权），但缺少 Artifact 概念。

**需要新增：**
- Artifact 创建、版本控制
- Artifact 共享与权限
- Artifact 搜索与发现
- 虚拟路径系统 `botfs://`

**改造方式：** 新建 `packages/artifact/` 模块。

### 6.6 新增 Governance

Tobs 已有 Approval（审批模板），DSH 已有 guard（守卫）。

**需要新增：**
- Policy Engine（策略引擎）
- Approval Flow（审批流程：Bot → Manager → Human）
- Audit Log（审计日志）
- Temporary Permission（临时权限）

**改造方式：** 新建 `packages/governance/` 模块，整合 Tobs 的 Approval 和 DSH 的 guard。

## 7. 组织协议

核心不是聊天，而是工作流。

### 7.1 协议流程

```text
User
 ↓
CEO (OrgBot)
 ↓ delegate
COO / CTO
 ↓ delegate
Director
 ↓ assign
Worker (PersonaBot)
 ↓ execute
Assignment Session
 ↓ report
Report (Artifact)
 ↓ review
Manager Review
 ↓ approve/reject
Decision
 ↓ escalate (if needed)
CEO
```

### 7.2 事件系统

在 DSH 的 SessionEventMap 基础上扩展：

```typescript
declare module '@deepseek-ai/dsh-session/types' {

    // 复用 DSH 已有

    'org/created': { orgId: string; name: string }
    'org/department_created': { orgId: string; deptId: string; name: string }
    'org/member_joined': { orgId: string; botId: string; deptId: string; role: string }

    'org/task_delegated': { taskId: string; fromBotId: string; toBotId: string }

    'org/report_approved': { taskId: string; approverId: string }
```

## 11. 三条不可变核心

整个项目从第一天就必须保护这三个接口。

### ① Organization Protocol

定义：

> Bot 如何工作、委派、汇报、审批、升级。

基于 DSH Team Task Board + Tobs Orchestrator 扩展。

### ② Runtime API

定义：

> DSH Agent Loop + Tobs PersonaBot Runtime 如何驱动组织中的 Bot。

直接复用 DSH 的 AgentRuntime / ComputerRuntime / StorageRuntime 接口。

### ③ Skill Protocol

定义：

> Skill、Tool、Connector、Workflow 如何进入数字员工体系。

基于 DSH Skill 注册体系扩展。

如果这三层稳定，未来可以不断替换底层 Runtime，也可以不断扩充 Skill 生态，而不用重写整个系统。
